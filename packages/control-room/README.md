# 协作控制中心（`@agent-relay/control-room`）

只读的可视化观察台：把 Relay 工作空间里的频道、智能体工作状态与消息流转放到一个本地页面上，
供人从“全局协作”一路追踪到“单条消息”。

界面需求与验收标准见 [`docs/design/relay-control-room/requirements.md`](../../docs/design/relay-control-room/requirements.md)。

## 快速开始

```bash
# 1. 构建工作区依赖
npm run build:core

# 2. 用演示数据启动（不需要任何凭据）
node packages/control-room/dist/cli.js --demo

# 3. 观察真实工作空间（只读观察者令牌）
node packages/control-room/dist/cli.js --token "$RELAY_CONTROL_ROOM_TOKEN"
```

打开终端输出的地址（默认 <http://127.0.0.1:4320>）。

推荐用 `agent-relay observer` 先签一个只读令牌，而不是直接把工作空间密钥交给控制中心：

```bash
agent-relay observer --workspace <工作空间> --expires 8h
```

## 参数

| 参数                  | 说明                                                            |
| --------------------- | --------------------------------------------------------------- |
| `--port <端口>`       | 监听端口，默认 `4320`                                           |
| `--host <地址>`       | 监听地址，默认 `127.0.0.1`；非回环地址需要显式 `--allow-remote` |
| `--base-url <地址>`   | Relay 服务地址，不填则使用部署默认值                            |
| `--token <凭据>`      | 工作空间密钥或只读观察者令牌 `ot_live_…`                        |
| `--refresh-ms <毫秒>` | 频道与工作状态刷新间隔，默认 `20000`                            |
| `--no-stream`         | 关闭实时事件流，只做定时刷新                                    |
| `--demo`              | 演示数据，不连接任何服务                                        |

环境变量：`RELAY_CONTROL_ROOM_TOKEN`（优先）、`RELAY_WORKSPACE_KEY`、`RELAY_API_KEY`、
`RELAY_CONTROL_ROOM_TZ`（界面时区，默认 `Asia/Shanghai`）。

## 安全模型

- 凭据只存在于本地服务进程内。浏览器拿到的只有视图模型，拿不到密钥，也无法直接访问 Relay API。
- 服务默认只监听回环地址。它持有的凭据可以读取整个工作空间，因此不应暴露到局域网或公网；
  远程查看请用 SSH 隧道转发 `127.0.0.1`。
- 控制中心**只调用读接口**：列频道、列成员、列消息、读会话事件、订阅只读事件流。
  它不会发消息、不会注册智能体、不会标记消息已读。
- 响应带 `Cache-Control: no-store` 与 `X-Content-Type-Options: nosniff`；静态资源做了路径穿越校验。

## 接口

| 方法   | 路径                           | 说明                                                 |
| ------ | ------------------------------ | ---------------------------------------------------- |
| `GET`  | `/api/health`                  | 服务存活、模式与目标地址（不含凭据）                 |
| `GET`  | `/api/bootstrap`               | 频道、智能体、主机、指标、连接状态、最近消息         |
| `GET`  | `/api/channels/:name/messages` | 分页消息，支持 `limit`、`before`、`q`、`from`、`day` |
| `GET`  | `/api/messages/:id`            | 单条消息                                             |
| `GET`  | `/api/search`                  | 服务端消息搜索（部署支持时）                         |
| `GET`  | `/api/stream`                  | SSE：`connection`、`message`、`agents`、`ping` 帧    |
| `POST` | `/api/pause`                   | `{"paused":true}` 冻结观察视图                       |

## 状态从哪来

界面上的每个状态都能说清依据，这是刻意的：

| 界面状态                    | 依据                                        | 没有依据时                               |
| --------------------------- | ------------------------------------------- | ---------------------------------------- |
| 执行中 / 等待 / 空闲 / 异常 | 智能体会话事件经 `reduceAgentActivity` 归约 | 显示“未知”，不显示“空闲”                 |
| 在线 / 离线                 | `agents.presence` 与智能体状态              | 显示“在线状态未知”                       |
| 频道“工作中”                | 与该频道明确关联的成员任务状态              | 只有近期消息时显示“近期有消息”           |
| 消息读取状态                | `readByCount` 或 `read` 事件                | 显示“读取状态未知”，不用“已发送”代替已读 |

“今日消息”只统计服务端已加载的频道，未覆盖全部频道时数字后加 `+`；无法统计时显示“暂无数据”。
吞吐图只画本进程实际观察到的事件，标注“本机观察”，不冒充历史指标。

## 连接状态

`正在连接 → 已连接 · 实时`，中断后进入 `重连中` / `连接降级` / `连接失败`，
界面顶部出现说明条并标注最后更新时间，此时不会继续显示“实时”。

暂停观察只冻结当前浏览器的前端视图，其他观察窗口、后台任务与事件照常运行。恢复时会重新读取一次最新状态，
并说明暂停期间的事件未逐条回放。

## 演示模式

`--demo` 使用完全相同的前端与接口，只是数据源换成内置的中文演示数据（8 个频道、23 个智能体），
每 12 秒生成一条演示消息。界面会显示“演示模式”标记，避免把演示数据当成真实运行状态。

## 已知边界

- 前端消息筛选作用于已加载的消息页；更早的记录需要点击“加载更早的消息”。
  服务端搜索接口已提供，但界面暂未把它接到输入框。
- 拓扑在频道较多时使用双环布局；超过约 20 个频道仍需聚合或按需展开。
- 全局拓扑只展开所选频道的成员；其他频道保留状态和成员数量。真实模式的连线表示成员关系，
  不循环播放模拟投递动画；演示模式保留流光，并标注“演示流转”。
- 未实现：发送消息、启停智能体、任务调度、告警、账号管理（不在只读观察范围内）。
- 主机信息依赖部署把智能体与主机关联起来（`metadata.host` / `metadata.node`），否则显示“主机未知”。

## 本地验收夹具

`scripts/seed-acceptance-workspace.mjs` 用本地引擎造一套可复现的验收数据：
6 个智能体覆盖执行中 / 等待 / 异常 / 空闲 / 离线，6 个频道覆盖工作中 / 待关注 / 空闲 / 已归档。

```bash
npx @relaycast/engine --db ./relaycast.db --port 8787          # 终端 A
KEY=$(curl -s -XPOST http://127.0.0.1:8787/v1/workspaces \
  -H 'content-type: application/json' -d '{"name":"acceptance"}' \
  | node -pe 'JSON.parse(require("fs").readFileSync(0)).data.api_key')
WS="$KEY" npm run seed:acceptance --workspace packages/control-room   # 终端 B，保持运行
```

脚本会每 20 秒给非 `backup` 的智能体发一次 `POST /v1/agents/heartbeat`：该引擎的在线状态只由
实时连接或心跳维持，观察者无法代持，所以夹具自己保持在线；`backup` 故意不发心跳，用来展示离线态。

## 部署兼容性（2026-10-26 本地引擎联调）

用 `@relaycast/engine` 11.0.0 实测后，本服务对以下差异做了适配：

| 差异                                                                | 处理                                                                    |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 会话事件返回 `{ id, type, payload, sequence }` 包装结构             | 自动解包，扁平结构同样接受                                              |
| 只接受 `session.*` / `status.*` / `tool.*`，拒绝 `turn.*`、`text.*` | 旧版 `status.*` 作为兜底证据，界面标注“依据：旧版状态事件（status.\*）” |
| `channels.list` 不返回成员，`agents.list` 不带频道归属              | 逐频道补读成员，并从成员反推智能体所属频道                              |
| `/v1/ws` 拒绝观察者令牌（401）                                      | 提示“未接受实时事件订阅，已改为定时刷新”，按 `--refresh-ms` 轮询        |
| 在线状态只来自实时连接                                              | 只读观察者无法代智能体心跳；没有真实智能体连接时一律显示离线            |

据此，观察一个没有活智能体的工作空间时，界面会如实显示“离线 / 未知”，这不是故障。
