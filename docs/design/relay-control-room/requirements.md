## 1. 产品目标与用户原始要求

为 Relay 提供具有未来科技感的可视化工作台，让观察者能从全系统协作状态，逐步追踪到具体频道、执行节点和单条消息。

| 编号 | 用户明确要求 | 对应界面 |
| --- | --- | --- |
| R01 | 界面有未来科技感，先看到设计效果 | 深色控制台、青色数据流、动态拓扑；可交互的本地原型 |
| R02 | 看到有哪些频道在工作 | 左侧频道列表、状态标签与工作中筛选 |
| R03 | 看到整个系统众多频道工作的科技数据流转视图 | 中间全局拓扑，展示频道、智能体与有方向的数据流 |
| R04 | 看出哪个节点正在工作 | 节点状态、执行中的视觉强调、节点详情与当前任务 |
| R05 | 选择频道后，看到频道状态和历史消息 | 频道详情面板，包含状态、成员、消息时间线 |
| R06 | 明确知道几点、谁给谁发了什么消息 | 日期、精确到秒的时间、发送者、接收对象和正文 |
| R07 | 长消息折叠，点击后放大查看 | 三行摘要、原地展开/收起、独立消息阅读窗口 |
| R08 | 先设计界面，再整理需求文档 | 本原型与本文档 |
| R09 | 界面必须全部使用中文（2026-10-26 补充） | 所有可见文案、导航、频道、节点、主机、状态、示例消息及弹窗 |

优先完成 R01—R07，并必须满足 R09。搜索、筛选、吞吐趋势、只读观察视角等是为这些要求补充的设计建议，不视为用户已经确认的新增范围。

## 2. 第一版设计方案

### 2.1 视觉方向

视觉主张：以石墨黑背景、细网格、清晰的节点关系和克制的青色流光，形成面向多智能体协作的科技控制台。

- 主色为青色，表示选中、执行和消息流转；琥珀色用于异常或等待处理的问题。
- 使用细分隔线组织工作区域，保持信息密度和层级，避免大量互相竞争的卡片。
- **全部界面必须使用中文。** 包括产品展示名、区块标题、频道和节点显示名、主机显示名、按钮、状态、时间说明、提示、无障碍名称、空状态、错误反馈和弹窗；不保留英文装饰性标语。
- 演示消息正文及动态生成的消息也全部中文化。技术标识与显示名分离，内部稳定标识不影响关联、筛选和路由；真实接入时应为系统对象提供中文显示名，不使用界面文案替换机制改写用户的原始消息。
- 时间、节点名、数字使用等宽字体，消息正文使用系统中文字体。
- 状态同时使用文字和形状，不单独依赖颜色或动画。
- 动效用于表达消息方向、状态变化和选中关系；支持暂停及系统的减少动态效果偏好。

### 2.2 信息架构

| 区域 | 主要信息 | 主要操作 |
| --- | --- | --- |
| 左侧导航 | 工作空间、频道名称、用途、工作状态 | 选频道、搜索、按状态筛选 |
| 顶部总览 | 工作频道数、执行中智能体数、消息量、待关注频道 | 暂停流转演示、跳转异常频道 |
| 中间主区域 | 全局逻辑拓扑、智能体节点、消息方向 | 点击频道/智能体、聚焦、缩放、拖动、重置、全屏 |
| 中间底部 | 吞吐趋势、最近消息流转 | 从最近流转进入消息详情 |
| 右侧详情 | 当前频道状态、任务、成员、消息时间线 | 查询历史、阅读消息、查看参与节点 |
| 消息阅读窗口 | 完整正文与收发上下文 | 复制全文、前后切换、关闭返回 |

桌面采用三栏布局，优先保障拓扑和消息阅读。窄屏时将拓扑和详情纵向排列，频道导航变为可横向滚动的列表。全局图用于观察概况，精确阅读节点信息使用频道聚焦或节点详情。

### 2.3 主要操作路径

1. 打开控制中心，先看到全局工作频道、执行节点及消息流转。
2. 点击左侧频道或图中的频道节点，右侧同步显示该频道的状态与历史消息。
3. 点击智能体节点，显示其当前任务、工作状态和所属主机；可继续切换至频道聚焦视图。
4. 在时间线中定位某条消息，直接阅读摘要，或原地展开。
5. 点击正文或放大按钮，在阅读窗口中查看完整内容；关闭后回到原先的位置。

## 3. 功能需求

### F01 频道列表与工作状态（R02、R05）

- 展示当前工作空间内用户有权查看的频道，包括频道名称、用途、状态和成员数。
- 清楚区分工作中、待关注、空闲、已归档；真实系统还需支持状态未知。
- 默认保留稳定顺序，避免状态变化导致用户正在点击的频道跳动；可提供“工作中优先”排序。
- 选中频道有持续、明显的视觉标记，并与拓扑、详情面板使用同一频道标识。
- 搜索可匹配频道名称及中文描述。原型提供全部、工作中、异常筛选。
- 已归档频道可以查询历史，不以归档状态推断所有成员离线。

### F02 全局数据流转图（R03、R04）

- 全局图显示工作空间、频道和智能体之间的逻辑关系。
- 频道节点与智能体节点在大小、形状、名称上区分；主机信息在智能体详情中展示。
- 流动粒子或沿线高亮表达有方向的消息传递。真实接入后，动态流转必须来自实际事件。
- 区分“属于某个频道”的静态关系与“刚发生消息传递”的动态关系；不能让没有事件的连线持续伪装为实时流量。
- 频道广播的目标是频道，不凭空绘制已向所有成员成功投递的连线。
- 点击频道高亮其关系；点击智能体显示节点详情。支持全局和频道聚焦两种范围。
- 提供放大、缩小、拖动、重置和全屏查看。失去选中对象时应给出原因并保留可恢复的全局视图。
- 大量频道时采用聚合和按需展开，避免默认绘制所有成员关系造成线条遮挡。

**图的语义：**原型中心的“协作中枢”表示工作空间的逻辑聚合，不代表实际所有消息都经过同一个物理服务器。原型连线和粒子为预设演示，不是对当前仓库运行流量的观测。

### F03 节点状态与当前任务（R04）

节点详情至少显示名称、节点类型、连接状态、工作状态、所属频道、当前任务和最近活动时间。智能体节点另外展示运行主机；信息缺失时显示“未知”或“暂无数据”。

| 状态 | 判断依据要求 | 视觉表达 |
| --- | --- | --- |
| 执行中 | 有有效任务/会话事件表明正在执行 | 青色节点、执行中文字，适度强调 |
| 等待 | 有明确等待任务、依赖或输入的状态 | 灰蓝色节点，显示等待原因 |
| 空闲 | 已确认在线且当前没有执行任务 | 静态节点、空闲文字 |
| 异常/阻塞 | 已确认错误、失败或未满足的必要依赖 | 琥珀色、异常形状、原因说明 |
| 离线 | 连接/心跳数据确认离线 | 虚线节点、离线文字、最后在线时间 |
| 未知 | 信息不足、状态过期或无法关联任务 | 单独的未知标记，不当作空闲 |

在线状态和工作状态必须分开。在线不能直接推断为执行中，近期有消息也不能直接推断为任务尚未结束。一个智能体可参与多个频道，工作归属需通过明确的任务/会话上下文确定。

频道“工作中”应根据与该频道明确关联的未结束任务或执行事件聚合。只有近期消息证据时，应描述为“近期有消息”，不冒充执行状态。具体事件与过期阈值在真实数据接入时核实。

### F04 频道详情（R05）

- 标题始终显示当前频道，包含状态、用途、当前任务摘要、参与成员和最近活动信息。
- 提供消息时间线与参与节点两个视图；切换视图不改变所选频道。
- 异常频道展示可理解的原因，例如“等待工程研发测试报告”，而不只有一个警告色圆点。
- 切换频道时取消或隔离上一频道的请求，迟到结果不能覆盖当前频道。
- 正式实现需记住各频道的阅读位置和筛选条件；原型切换频道时重置消息筛选与滚动位置。

### F05 消息时间线与历史查询（R05、R06）

每条消息应包含：

| 字段 | 展示要求 |
| --- | --- |
| 日期与时间 | 日期分组，时间精确到秒；明确时区，默认北京时间（东八区） |
| 发送者 | 可识别的显示名，内部保留稳定 ID |
| 接收对象 | 智能体、频道或会话；不能用当前选中频道猜测收件人 |
| 消息类型 | 频道消息、私信、群组私信或线程回复等 |
| 正文 | 保留换行与完整内容，长内容支持折叠 |
| 状态 | 根据实际证据显示已入队、投递、已读等；缺失时标为未知 |
| 追溯标识 | 详情窗口展示消息 ID；存在时保留线程和父消息关系 |

- 原型采用最新在上的顺序。正式版本以服务端时间排序，同时间用事件序号或稳定的消息标识确定顺序。
- 历史记录分页加载并去重。先加载最近一页，再获取更早历史；进入频道时处理好历史快照与实时增量的重叠。
- 支持按正文、发送者、接收对象搜索；提供发送者和时间范围筛选。原型提供今日、昨日、全部历史。
- 用户阅读旧消息时保留滚动位置，新消息通过提示按钮告知；只有用户明确点击才跳回最新位置。
- 系统消息与普通消息应易于区分；加载中、没有消息、没有搜索结果和读取失败分别呈现。

**私信关联规则：**频道历史与私信会话是不同的数据范围。只有显式任务/会话关联且用户具备权限时，才能将私信作为“关联私信”放入频道视图。不能因为发送者和接收者都加入某频道，就自动将私信归入该频道。原型中的关联私信为人工构造的演示记录。

**投递语义：**发送成功可能只确认入队，不代表已被读取。界面不得用“已发送”替代“已读”，也不得根据时间推断读取状态。

### F06 长消息与放大阅读（R07）

- 建议默认显示三行摘要。正式实现按实际排版后的溢出判断是否折叠；原型使用文本超过 130 个 UTF-16 码元或超过三段换行的规则识别长消息，再限制为三行。
- 折叠时提供“展开全文”和字数提示；展开后可原地收起。
- 点击正文或放大按钮进入独立阅读窗口，完整内容不因摘要裁剪而丢失。
- 阅读窗口保留频道、日期时间、发送者、接收对象、消息类型、消息状态及消息 ID。
- 正文独立滚动，顶部上下文和底部操作保持可见。支持复制全文、上一条、下一条。
- 支持关闭按钮、Esc 和遮罩关闭；关闭后恢复触发控件的键盘焦点及原有阅读位置。
- 用户可选择并复制正文。复制失败要给出真实反馈，不能假装已复制。
- 正式实现需处理安全的 Markdown、代码块、超长单行、链接和附件；原型采用转义后的纯文本显示，已支持换行和长词换行。

### F07 汇总与趋势（设计建议）

- 汇总工作频道数、执行中智能体数、今日消息数和待关注频道数。
- 消息计数以稳定消息 ID 去重，以明确的工作空间和时区定义“今日”。
- 吞吐图明确单位、统计窗口和时间轴；历史与实时数据不能重复计数。
- 数据不可用显示“暂无数据”，不得以 0 替代未知。
- 原型的今日总量、昨日对比、趋势柱图为独立的演示统计，不等于原型中有限的历史样例条数，也没有 CPU、GPU 或 token 消耗的真实监控数据。

## 4. 实时连接、交互与可用性规则

| 场景 | 正式界面预期 |
| --- | --- |
| 初次连接 | 显示加载或连接状态，不绘制虚假的实时流转 |
| 连接正常 | 按事件增量更新，尽量保持节点布局和用户焦点稳定 |
| 暂停观察 | 冻结前端观察视图，后台任务继续运行；恢复后补齐或刷新，并说明中间事件处理方式 |
| 连接中断 | 保留最后数据并标明断开/重连、最后更新时间；不能继续显示“实时连接正常” |
| 恢复连接 | 从已确认游标恢复并去重；无法补齐时明确标出缺失区间 |
| 无权查看 | 明确显示权限限制，不以空频道伪装 |
| 频道被归档或节点消失 | 更新状态，保留有权限的历史与上下文 |
| 减少动态效果 | 关闭循环流光与旋转，仍保留方向、状态和文字信息 |

基本操作支持键盘，控件有可访问名称；详情标签支持方向键切换，弹窗限制焦点并在关闭后恢复。正式版本需要另外检验屏幕阅读器、对比度、触摸目标和大规模数据性能。

## 7. 本次范围与后续待定事项

本次已交付可交互的静态设计原型和需求文档。首版默认采用单工作空间、只读观察的工作台方向；发送消息、启动/停止智能体、任务调度、告警通知、账号管理不在这次原型范围。

后续实现前需要确定：

1. 视觉方向与信息密度是否保留；语言已确定为全部中文，后续只讨论中文名称的具体措辞。
2. “节点”是否还要在主拓扑中包含物理主机、Broker、工具和外部服务；原型主要节点为频道与智能体。
3. 当前部署可提供哪些任务事件，怎样准确判断某个频道正在工作。
4. 历史保留范围、可查看的私信权限以及私信关联频道的依据。
5. 最终界面作为独立本地服务、CLI 可选入口，还是单独前端项目提供。
