# ZCode MCP 权限选择研究、实现与本机部署

日期：2026-11-06。Relay 源码 `8cf792515`；HuBoZhi/zcode_mcp 源码 `5332def`。

## 研究结论

ZCode 权限模式控制操作确认策略，不等于操作系统目录或网络隔离。
[官方安全确认说明](https://zcode.z.ai/cn/docs/safety-confirm)描述计划、变更前确认、自动编辑与完全访问。
本机 ZCode 的协议枚举还包含 guarded（自主模式）和兼容用 auto。

本机安装包确认支持 `session/setMode`，参数为 sessionId、mode 和可选 expectedRevision。
MCP 原已有 zcode_run.mode，但只用于新建会话；接续会话没有应用该参数。Relay 则固定使用连接配置中的 mode，没有每次派活的选择入口。

## 实现

- MCP 在发送提示词前设置权限并验证后端回显；接续显式指定模式时也应用。未指定模式的接续调用保留旧模式，未改变直接 MCP 新会话的既有默认值。
- 新增 zcode_set_mode，可修改已有空闲会话且不发送提示词；本进程正在执行的回合拒绝权限切换。
- 当前后端的计划模式是 planEnabled 覆盖层，快照 mode.current 仍为底层模式，必须核对 session/events。
- 缺少计划变更历史时，在空闲状态重设相同底层权限后进入计划模式，获取明确事件证据；期间不发送提示词。不确认成功时不会派发模型任务。
- Relay 通过 session.permissionMode 保存和传递选择，支持群聊每个 ZCode Agent、任务工作台每个阶段，包括接续会话。
- 界面提供连接默认、计划、变更前确认、自动编辑、自主、完全访问。保留连接默认行为，不替用户默认选择完全访问。
- 群聊草稿保存选择，请求显示“请求权限”；更换任务客户端时同步禁用/启用权限框。旧版 MCP 不支持已验证权限切换时明确拒绝，不静默忽略。
- 无头 MCP 的交互请求仍拒绝处理，不代替用户批准；需要确认的模式可能无法完成涉及审批的操作。此限制在界面中直接说明。
